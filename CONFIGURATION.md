## Configuration File Overview

PiPilot reads its settings from:
```
pipilot/config.yaml
```
*(If `config.yaml` is not present, PiPilot will fall back to `config.example.yaml`)*.

> [!TIP]
> You can also supply your bot token via the `TELEGRAM_BOT_TOKEN` environment variable to keep your token out of the YAML file.

## 1. Telegram Bot & Authentication (`bot`)

Controls bot credentials, authorization guard, and startup alerts.

```yaml
bot:
  # Telegram bot token generated by @BotFather
  token: "1234567890:ABCdefGHIjklMNOpqrsTUVwxyz"

  # List of authorized Telegram numeric Chat IDs
  admin_chat_ids:
    - 123456789  # Replace with your numeric Telegram user ID from @userinfobot

  # Broadcast a message to admins when Pi boots up
  send_startup_message: true
```

### Parameters
| Field | Type | Default | Description |
| :--- | :--- | :--- | :--- |
| `token` | string | `""` | Your Telegram Bot API token from [@BotFather](https://t.me/BotFather). |
| `admin_chat_ids` | list of ints | `[]` | Numeric Telegram IDs authorized to control the bot. Unauthorized users are blocked automatically. |
| `send_startup_message` | boolean | `true` | If `true`, sends a Telegram notification on Pi boot with IP, Wi-Fi SSID, CPU temp, and uptime. |

> [!NOTE]
> **How to find your Telegram Chat ID:**  
> Message [@userinfobot](https://t.me/userinfobot) or [@RawDataBot](https://t.me/RawDataBot) on Telegram. It will reply with your numeric `Id`.

## 2. Periodic Health Reports (`periodic_status`)

Broadcasts regular hardware resource updates directly to your chat without typing commands.

```yaml
periodic_status:
  enabled: true
  interval_minutes: 180 # e.g. 180 = every 3 hours
```

### Parameters
| Field | Type | Default | Description |
| :--- | :--- | :--- | :--- |
| `enabled` | boolean | `true` | Set to `false` to turn off periodic background status reports. |
| `interval_minutes` | integer | `180` | Delay in minutes between consecutive status reports (e.g., `60` = 1 hour, `180` = 3 hours, `360` = 6 hours). |

## 3. System Power & Network (`system`)

Defines how power actions are triggered and which network interface to prioritize for IP discovery.

```yaml
system:
  reboot_cmd: "sudo reboot"
  shutdown_cmd: "sudo shutdown now"
  preferred_interface: "wlan0"
```

### Parameters
| Field | Type | Default | Description |
| :--- | :--- | :--- | :--- |
| `reboot_cmd` | string | `"sudo reboot"` | Shell command executed when confirming reboot. |
| `shutdown_cmd` | string | `"sudo shutdown now"` | Shell command executed when confirming shutdown. |
| `preferred_interface` | string | `"wlan0"` | Interface name to display as primary (`wlan0` for Wi-Fi, `eth0` for Ethernet). |

## 4. Application & Service Management (`services`)

PiPilot allows you to manage any number of custom shell scripts or Linux systemd services directly from Telegram inline buttons.

```yaml
services:
  # Example 1: Custom shell script service
  - id: "webapp"
    name: "Web Application"
    type: "custom" # "custom" or "systemd"
    start_cmd: "/home/pi/scripts/start_webapp.sh"
    stop_cmd: "/home/pi/scripts/stop_webapp.sh"
    restart_cmd: "" # Leave empty to auto-run stop then start
    log_file: "/home/pi/logs/webapp.log"

  # Example 2: Background Python or worker script
  - id: "worker"
    name: "Background Worker"
    type: "custom"
    start_cmd: "/home/pi/scripts/start_worker.sh"
    stop_cmd: "/home/pi/scripts/stop_worker.sh"
    restart_cmd: ""
    log_file: "/home/pi/logs/worker.log"

  # Example 3: Native systemd daemon
  - id: "api_service"
    name: "Systemd API Service"
    type: "systemd"
    service_name: "my-api.service"
    log_file: "/var/log/my-api.log"
```

### Parameters
| Field | Type | Required | Description |
| :--- | :--- | :--- | :--- |
| `id` | string | **Yes** | Unique identifier (used internally in Telegram callback buttons). Avoid spaces. |
| `name` | string | **Yes** | Display name shown on buttons and notification cards. |
| `type` | string | **Yes** | Either `"custom"` (shell scripts) or `"systemd"` (Linux systemctl). |
| `start_cmd` | string | For `custom` | Absolute command/script path to start the app. |
| `stop_cmd` | string | For `custom` | Absolute command/script path to stop the app. |
| `restart_cmd` | string | Optional | Command to restart. If left empty `""`, PiPilot automatically runs `stop_cmd` followed by `start_cmd`. |
| `service_name` | string | For `systemd` | Systemd service unit name (e.g. `nginx`, `docker`, `my-api.service`). |
| `log_file` | string | Optional | Path to application `.log` file for viewing and downloading via Telegram. |

## 5. Log Inspection & SD Card Retention (`logs`)

Configures log tail previews and post-download retention to protect Raspberry Pi SD cards from filling up.

```yaml
logs:
  default_tail_lines: 50
  post_send_action: "truncate" # Options: "none", "truncate", "delete"
```

### Parameters
| Field | Type | Default | Description |
| :--- | :--- | :--- | :--- |
| `default_tail_lines` | integer | `50` | Number of lines to preview directly in the Telegram chat when clicking "View Last 50 Lines". |
| `post_send_action` | string | `"none"` | Action performed after downloading full log document via Telegram. Options: `none`, `truncate`, or `delete`. |

> [!TIP]
> **Why `truncate` is recommended for active apps:**  
> Truncating (`post_send_action: "truncate"`) resets the file size to 0 bytes while keeping the file descriptor open, allowing active background daemons to continue logging uninterrupted without throwing "File Not Found" errors.

## 6. Multi-Runtime Process Inspectors (`inspectors`)

Allows you to inspect active processes across Java, Python, and JavaScript without logging into SSH.

```yaml
inspectors:
  java:
    enabled: true
    jps_path: "/home/pi/.sdkman/candidates/java/current/bin/jps" # or "jps"

  python:
    enabled: true
    exclude_self: true # Exclude PiPilot process itself from list

  javascript:
    enabled: true
    pm2_enabled: true  # Automatically query PM2 process status
```

### Parameters
- **`java`**:
  - `enabled`: Toggle Java process inspector (`/java` or `/jps`).
  - `jps_path`: Path to Java's `jps` binary. If Java is in standard PATH, simply use `"jps"`.
- **`python`**:
  - `enabled`: Toggle Python process inspector (`/py` or `/python`).
  - `exclude_self`: Hides PiPilot from the list so you only see your actual background scripts.
- **`javascript`**:
  - `enabled`: Toggle JavaScript process inspector (`/js` or `/node`).
  - `pm2_enabled`: Displays PM2 process table if PM2 is installed.

## 7. How to Apply Config Changes to Your Pi

Whenever you update `config.yaml`, the running PiPilot background service must be reloaded. Follow these steps:

### Option A: If editing locally on your PC (via Git)
> [!WARNING]
> `config.yaml` is ignored by `.gitignore` by default to prevent accidentally exposing your Telegram bot token in public git repositories. If you manage configuration across multiple devices via Git, ensure your repository is **private** before tracking `config.yaml`, or use environment variables (`TELEGRAM_BOT_TOKEN`).

1. Edit and save `config.yaml` on your computer.
2. Commit and push (if in private repo):
   ```bash
   git add config.yaml
   git commit -m "Update service configuration"
   git push
   ```
3. On your Raspberry Pi, pull and restart:
   ```bash
   cd ~/pipilot
   git pull
   sudo systemctl restart pipilot
   ```

### Option B: If editing directly on your Raspberry Pi (Recommended)
1. Open the file with a terminal editor:
   ```bash
   cd ~/pipilot
   nano config.yaml
   ```
2. Make your edits.
3. Save: Press `Ctrl + O`, then `Enter`.
4. Exit: Press `Ctrl + X`.
5. Restart the service:
   ```bash
   sudo systemctl restart pipilot
   ```

### Verify Service Status & Logs
```bash
# Check if running cleanly:
sudo systemctl status pipilot

# Follow live output:
sudo journalctl -u pipilot -f
```

## 8. Troubleshooting & YAML Tips

1. **Indentation Matters:** YAML requires spaces (usually 2 spaces per indentation level). Never use tabs (`\t`).
2. **Missing Quotes in Tokens:** Always wrap bot tokens and commands with special characters in double quotes:
   ```yaml
   token: "1234567890:AA..."
   ```
3. **Verify File Exists Before Testing:** Ensure your `start_cmd`, `stop_cmd`, and `log_file` paths exist on the Raspberry Pi filesystem and have execute permissions (`chmod +x script.sh`).
4. **Invalid Syntax Check:**
   You can verify YAML syntax on your Pi anytime with:
   ```bash
   python3 -c "import yaml; yaml.safe_load(open('config.yaml'))" && echo "YAML is valid!"
   ```
